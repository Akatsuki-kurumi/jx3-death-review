# 首次发布到 GitHub

目标仓库：`Akatsuki-kurumi/jx3-death-review`。代码采用 MIT，署名 `Akatsuki-kurumi`，保留版本 `0.1.0`。

## 1. 确认公开内容

公开应用源码、合成测试、开发说明、LICENSE，以及维护者指定保留的 Buff 字典等资料。头像、真实 JCL、个人报告、研究目录、截图、密钥和本地缓存已加入忽略规则；这些本地文件不会被删除。

先阅读 `THIRD_PARTY_NOTICES.md`。Buff 字典与游戏资源的再分发许可仍有未确认部分；不能只因项目使用 MIT 就宣称它们也获得 MIT 授权。后续补充原作者、发布页及许可。旧 dist 压缩包含个人头像，不要上传该包到公开 Release。

## 2. 创建一个空的公开仓库

打开 https://github.com/new ：Owner 选择 Akatsuki-kurumi；Repository name 填 jx3-death-review；Visibility 选择 Public。

不要在 GitHub 网页勾选生成 README、.gitignore 或 License，因为本地已经准备好。仓库创建后复制 HTTPS 地址。

## 3. 首次提交与推送

在本项目目录的 PowerShell 中操作。下面的 `git add` 应在公开文件检查及干净源码测试通过后执行。

```powershell
git status --short
git add .
git diff --cached --stat
git diff --cached --name-only
git commit -m "Initial open-source release"
git branch -M main
git remote add origin https://github.com/Akatsuki-kurumi/jx3-death-review.git
git push -u origin main
```

已有 origin 时先用 `git remote -v` 核实，勿盲目覆盖。Git 提交若提示身份未设置，配置你希望公开的署名和 GitHub 提供的 noreply 邮箱，不必公开私人邮箱。无需把 GitHub Token 粘贴到聊天或源码中。

## 4. 验收仓库

检查 GitHub 首页 README、MIT License、版本号及公开文件清单。从仓库重新克隆，安装依赖、运行测试，并启动网页和桌面。确认没有头像也可启动，Buff 字典能读取。

## 5. 可选：发布 Windows 下载

在干净的公开源码中执行 `pnpm package:open-source`，验证生成程序，压缩 `dist/open-source/v0.1.0/` 下的完整发行目录，使用带“开源版”标记的 ZIP 文件名。GitHub Releases 新建 tag `v0.1.0`，上传新生成 ZIP 和校验摘要。原版 `dist/v0.1.0/` 及旧压缩包必须保留，不覆盖，不上传含个人头像和本机缓存的历史本地发行包。
